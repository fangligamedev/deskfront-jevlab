# 工程文档

## 状态与数据流

Godot 4.5.1 / GDScript 是唯一战斗状态来源。scenes/main.tscn 加载 scripts/game.gd，读取 JSON 规则、地图和运行资产。Web 是同一 Godot 工程的导出。

玩家输入、游戏 AI、LM 和外部 Agent 都经过引擎校验，再由单位执行；Python 负责命令排队和 LM 调度，网页只显示快照与回执。HTTP 202 不表示游戏已经执行成功。

## 战斗执行

- 物理 tick 更新单位、弹道、压制和得分。暂停冻结模拟时间，仍处理控制消息。
- game_ai / lm / agent / player 按阵营互斥；换控递增 control_epoch，旧 LM 回复失效。
- LM 独立调用每名存活步兵和坦克；模型仅选意图，不负责直接写血量或位移。
- 战术协调与单兵执行分层。推进需要实际近期掩护火力，危险时先自保。关注坦克不应忽略侧后方步兵。
- 导航使用 0.025 米 A* 栅格；坦克使用膨胀障碍。掩体站位预约有空间互斥，破坏更新导航 revision。
- 弹丸分段测试真实几何的首个交点，单位命中盒随姿态/朝向变化；不是逐三角碰撞。爆炸先判断遮挡，再破坏与结算。
- Actor 根运动回写单位位置，避免与旧线性位移叠加。楼梯沿真实高差运行，撤离排队；没有传送到二楼。
- 设施操作不会被普通小队队形覆盖；轻武器不攻击坦克，炮手受压制或重伤会弃炮。
- 固定种子可复现受控演练，但输入到达 tick、浮点环境与模型网络时延会影响结果，不保证跨平台逐位确定性。

详细行为见 [战术说明](TACTICS.md) 和 [动作状态契约](AGENT_ACTION_STATES.md)。

## 服务与模型

本地 Python 服务只绑定 127.0.0.1。普通玩法不需要外部网络；启用 LM 才向允许的火山方舟 HTTPS 推理地址发请求。Key 不传给浏览器或 Godot。预算、并发、超时和来源标识见 [LM 控制](LM_CONTROL.md)。

一个服务端口只由一个实际游戏实例控制。Web 控制台先调用 `POST /api/session` 领取 `instance_id`，再把它交给自己的游戏 iframe。新页面明确接管服务后，旧实例的同步、回执和控制命令都不能改写新对局；旧页面显示断开提示。原生实例在未被 Web 接管的服务上首次同步时登记实例号，原生观察页面使用 `?native`，不会启动第二个游戏。切换回原生实例时重启本机服务并先启动原生游戏。当前没有多用户认证或多实例路由，实例号仅隔离本机运行会话，不是认证凭据；不可直接部署公网，见 [安全说明](../SECURITY.md)。

`scripts/bridge.gd` 将实例号和待发送回执保存在 SceneTree 元数据中，换地图或重开销毁场景后仍可上报真实执行结果。服务不会仅因 run_id 改变就猜测重开成功。控制台给每条命令携带 instance_id、run_id，并跟踪所有待返回命令；下拉框读取实际步兵装备和姿态，姿态指令排除坦克。`tests/test_control.py` 覆盖旧实例隔离、过期观察、场景重载回执和禁止伪造成功。

## 数据、输出与测试

data/battle.json 定义规则；data/sandbox-maps.json 定义地图、出生点、建筑和火炮。控制台调参只影响本局，重开恢复 JSON。data/action-catalog.json 为机器可读动作合同。

output/session.jsonl 记录真实状态、排队指令与回执；目前没有完整回放播放器、训练调度或战争迷雾。固定种子、Godot 合同、Python 测试和真实浏览器输入共同验证行为，不能以导出成功代替验证。

完整命令见 [开发指南](DEVELOPMENT.md)，发布条件见 [发布流程](RELEASING.md)。历史演进见各版本交付报告，当前架构以本页和代码为准。
