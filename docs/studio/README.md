# AI 战术沙盒

Deskfront 的目标是让一个模型完成三类工作：**创造可玩的对抗关卡、在规则内指挥作战、根据真实过程解释战局**。玩家可以在任何阶段接管，游戏规则与物理执行始终归 Godot。

## 完整体验

1. 启动项目，打开策划台顶部 **AI 创作沙盒**。
2. 描述希望玩家体验的战术取舍，例如绕侧、火力掩护、反装甲或旗区轮换。
3. 点击 **让 LLM 创建战术关卡**。服务调用已配置的 DeepSeek；失败时把校验错误反馈给模型，最多再修正一次。
4. 查看布阵预览、玩家简报、战术意图与 Godot 通路检查结果。也可以编辑 JSON 后点击 **校验并保存 JSON**。
5. 选择玩家阵营、其他阵营由游戏 AI / DeepSeek LLM / 外部 Agent 控制，点击 **进入关卡**。场景更换后暂停待开始，点击战场的 **继续** 开局。
6. 玩家用现有 RTS 鼠标操作参与；控制台可随时切换各队控制。士兵、坦克继续拥有底层保命、导航和武器规则。
7. 点击 **分析当前战局** 获取该时刻的态势分析。自定义关卡结束后自动生成一次战后报告；失败可以手动重试。
8. 导出关卡 JSON 与报告 JSON，用于分享、复现布局、对比设计。导出关卡不含模型密钥。

## 三种模型角色，共用一个连接

| 角色 | 输入 | 输出 | 谁验证 |
| --- | --- | --- | --- |
| level-designer | 玩家意图、场景目录、JSON Schema、上次校验错误 | 三方部署、装备、掩体、旗点、守旗时长及设计意图 | Python 结构校验 + Godot 实际导航 |
| 每个士兵 / red-tank | 当前单位、敌友、掩体、旗点、进展和历史行动 | 单单位战术动作 | 既有动作协议和 Godot 控制权 / 生存 / 武器校验 |
| battle-analyst | 同一局的事实统计、时间采样、事件和允许引用的 Tick | 态势或战后分析、三方优缺点、取胜关键、不确定性 | 报告结构、阵营与 Tick 引用校验 |

创建和复盘也是实际 LLM 调用，全部进入 **LLM 调用日志**。设计成功显示“关卡校验通过”，报告成功显示“分析报告已保存”；这两者不会伪装成战斗指令回执。默认连接为火山方舟 DeepSeek；外部模型也可通过公开 JSON/API 生成关卡和操作游戏，或在 Python 中替换 `complete(payload, trace)` 适配器。

## 关卡契约与边界

首版在已有三张桌面地形上创建战术关卡，复用办公室、小楼、反坦克炮和模型资产；不是任意游戏类型生成器，也不执行模型生成的代码。每队固定 3 名步兵，红方保留一次可见坦克增援。

模型可以布置 4–14 个沙包/木箱，选择三方出生中心和各兵武器，调整中央旗点与 20–90 秒守旗时长。每队至少一名火箭兵，保留反装甲反制。固定地形、楼梯、小楼、河流和桥梁不能由模型绕过校验篡改。关卡必须实际改变布置或配置，只有改文案的生成结果会被拒绝。

结构定义：[JSON Schema](../../data/studio-scenario.schema.json)；示例：[studio-example.json](../../data/studio-example.json)。Python 检查类型、边界、数量、尺寸、装备和允许字段；Godot 使用生产地图同一规则转换与 AStar 网格检查九个出生点到旗点的路径、至少两个开阔接近方向及部署距离比。加载时引擎再次验证，失败不替换现有对局。

通路可达不等于战术平衡。入口数量也不代表两条完全独立的路线。平衡性、玩家难度与趣味性仍需要多局评估。

## 报告中的事实和推断

服务按游戏时间约每 2 秒保存一次快照，记录各兵位置、武器、血量、掩体状态、指令、最后射击，以及旗点、累计射击和破坏数量。报告最多选取贯穿整局的 16 个时间点；完整采样保存在本机。

报告同时保存 `evidence_input` 和 `analysis`。前者来自引擎，后者是模型解释。引用 Tick 必须实际存在；这可以阻止编造引用位置，不能自动证明每一句因果推断。射击不是命中数，时间采样不是逐帧回放。模型必须列出不确定性。分析输入明确 +x 向右、+z 向下；关卡简报另存为未验证的 design_intent，不作为已发生战况。

报告与 `run_id`、`scenario_id` 绑定。局次变更不会改写旧报告；自定义对局结束自动提交一次报告任务，服务重启后也避免对已提交局次重复自动生成。中途态势分析需要手动点击，不持续消耗模型调用。

## 存储与费用边界

- `output/studio/studio.sqlite3`：关卡、异步任务、按局采样和报告。
- `output/lm-calls.sqlite3`：三种角色的输入、原始返回和校验 / 执行结果，凭证脱敏。
- `output/` 不提交 Git。开源的是实现、契约、示例和测试，不是本机 Key 或个人对局。

创作/分析最多两个并发任务，发起间隔至少 2 秒；一次生成最多两次模型请求，一次报告一次请求。它们与逐兵的单局 600 次上限分开计数，均可在调用日志查看。无模型配置时仍可导入 JSON 并使用游戏 AI。
