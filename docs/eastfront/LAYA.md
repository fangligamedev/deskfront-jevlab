# Laya 本地决策接入

Laya 是本地 System One 决策模型，不是 LayaAir 游戏引擎。Godot 继续拥有战斗状态、导航、弹道、施工和胜负的执行权。可以替代 JEV 的结构化选择接口，不代表两个模型的决策质量或概率校准相同。

## 页面入口

在「无尽东线」中：

- **快慢脑 · DeepSeek 规划 + Laya 本地执行**：DeepSeek 规划未来三段，Laya 选择队伍战术意图与工兵施工顺序。远征队控制推荐「游戏 AI · 小队协同」。
- **Laya · 本地构筑防线**：Laya 直接从合法模板中选择后续防线，无需 DeepSeek。
- **Laya · 本地逐兵指挥**：每个步兵或坦克根据自己状态、附近敌人、有效射界与候选动作进行决策。游戏引擎连续执行，保留自保与指令合法性检查。

点击「开始新东线」应用建场配置；「应用控制方式」可改变当前远征队控制。逐兵模型切换是全局配置，会影响所有处于模型控制的阵营；玩家和外部 Agent 控制不受覆盖。JEV、DeepSeek 原有入口保留。

## 本机配置

先运行用户已部署的 Laya 服务，再启动本游戏服务：

```dotenv
LAYA_BASE_URL=http://127.0.0.1:9400
# 可选：启动时默认逐兵模型
DESKFRONT_LM_PROVIDER=laya
```

无需 Laya Key。适配器仅接受 `http://127.0.0.1:端口` 或 `http://localhost:端口`，无额外路径、用户信息或查询参数；不跟随跳转、不使用系统 HTTP 代理。当前不连接 Railway 云端。

`GET http://127.0.0.1:9400/ready` 应返回 200。`configured=true` 表示本地连接配置可用，不等于模型已加载；未启动、忙碌、超时的真实错误会进入调用日志。游戏服务不会擅自启动、停止或修改共享 Laya 服务。

## 协议和边界

- 本地接口：`POST /v1/systemone`，发送 `state / questions / allow_truncation:false`，移除 JEV 专属的 `model` 字段。
- 紧凑投影只保留决策相关状态；不发送完整几何、日志历史和模型长篇策略。服务端一旦报告任何截断警告，本次结果拒绝执行。
- `choice` 的选项、完整概率分布、置信度以及 `noul` 范围均校验；未知选项不下发。
- 坦克不接受步兵姿态；轻武器不能选择攻击坦克。模型不能改血量、导航或运行代码。
- 逐兵请求最多一个在途；快脑约每两秒请求一次、每种脑最多一个在途。共享服务忙碌时的 429、连接失败和超时真实记录，延用现有本地保护与生成兜底。不会偷偷改用 JEV 或把本地保护标成 Laya 决策。
- 快脑仍保留每局 300 次、慢脑 64 次预算；逐兵采用原有每局调用预算。超限后不伪造新模型结果。
- Laya 返回的是编码器决策分布，不生成战报长文；战局报告与完整关卡规划继续使用 DeepSeek。

API：`eastfront_start.backend` 新增 `laya / dual_brain_laya`；`POST /api/lm/provider` 的 `provider` 新增 `laya`。`/api/lm/status` 与调用日志保留模型名、输入、原始输出、耗时和引擎执行回执；Laya 指令来源分别为 `laya` 与 `laya_fast`。

## 验证

新增接口测试覆盖免密配置、仅本机端点、准确线协议、禁止静默截断、步兵/坦克动作、非法选择、输入投影、模型忙碌和后端枚举。实测证据见 [Laya 接入证据](../evidence/eastfront/laya-integration.json)。本机耗时为样本测量，不保证任意硬件和并发下相同。
