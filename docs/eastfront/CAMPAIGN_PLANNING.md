# 慢脑战役方案与塑料工兵修复交付

2026-09-21。

## 根因与实现

此前慢脑只返回三个模板 ID，没有可执行的守军编成、工位和装甲字段；东线未连接原地图的坦克入场链路，守军沿用旗点 AI，施工人员是方块几何。完整规划又与逐兵响应共用短超时，因此界面显示“快慢脑”并不代表这些行为已由慢脑安排。

现在 DeepSeek 一次规划三段：模板、2–3 名守军及不同工位、施工优先级、防守意图、双方装甲与延迟/角色。本地 Laya 或 JEV 每轮选择推进、施工、守军、装甲四类指令，Godot 连续执行并返回真实回执。完整协议见 [DUAL_BRAIN.md](DUAL_BRAIN.md)。

守军有独立的计划执行分支，先寻路进入指定掩体；被压制或工事被摧毁时保留原有保命逻辑并重选有效掩体。横向沙包工位加宽并补充端部保护槽，保护判断仍需通过遮挡、身体四角和可达性检测。坦克先可见待命，经快脑放行沿导航路线慢慢驶入，只有入场后才能开火。存活坦克跨段复用，步兵覆灭时不会被存活坦克阻止补兵。

工兵复用当前 `toy-soldier.glb` 塑料网格和骨架，跑动/蹲姿配合铲子与沙包的持握 IK，保留分阶段挖掘、搬运、堆砌。没有新增方块人体，也没有覆盖已有美术资产。

## 验证结果

- Python 接口测试 91 项通过。
- Godot 语义检查 113 项通过。
- 六种关卡 × 17 项战役断言，共 102 项通过：实际入掩体、不同站位、塑料骨骼、双方坦克待命/驶入/参战、入场前禁火、玩家控制边界及步兵补兵。
- 原快慢脑 17 项与战术回归 13 项通过；Forge 检查通过；Web 导出成功。
- 真实 DeepSeek + 本地 Laya 浏览器对局：三次慢脑请求成功并由引擎接受，规划返回约 5.1 / 5.8 / 6.9 秒；自动突破六段，双方坦克均实际入场参战。并非以手写方案冒充模型结果。记录见 [campaign-planning.json](../evidence/eastfront/campaign-planning.json)。

## 边界与使用

打开无尽东线，保留默认“DeepSeek 规划 + Laya 本地执行”和“Laya 本地战术指挥”，开始新东线。旧局不会自动替换成新方案。右侧每段显示守军武器/工位、战术理由、双方坦克待命与入场状态，LLM 日志保留规划输入输出与执行回执。

关卡仍使用六种已登记组件布局；模型不能生成任意代码或未知资产。战壕为桌面上的浅壕工位表现，没有真实地形挖穿。工兵是施工表现实体，不参加战斗。JEV 共用同一接口与执行合同，本轮真实模型联调使用 DeepSeek + Laya，未另计费复测 JEV。共享 Laya 服务出现过 429，已有退避；慢脑故障时明确等待，新段不再偷偷使用本地模板，已建战场持续运行。
