# 夺旗倒计时与 LM 败北预警

版本：0.6.5-flag.1。主游戏入口：http://127.0.0.1:8768/ 。

## 完成内容

- 夺旗开始显示剩余 30 秒；网页和 Godot 原生画面均有醒目横幅，最后 10 秒变红。
- 另外两个阵营的 LM 输入包含明确中文败北军令、占领方、剩余秒数、争夺状态，任务优先级提升为 critical，允许承担伤亡。
- 新占领及 15 / 10 / 5 秒节点优先重新决策；丢弃旧占领轮次的模型返回和排队命令。
- 敌方守旗时，LM 反攻不再被普通自动保命撤退覆盖；仍遵守碰撞、路径、压制、伤害、单位权限及动作限制。
- 模型不可用时，本地回退尝试反攻，日志如实标记 local_fallback。
- 多方争夺暂停倒数；原守方离开、被清除或旗点换手后按既有规则清零重计。胜负由 Godot 判定，网页不自行计时。

## 验证证据

`engine.json`：17 项新增引擎检查，含起始 30 秒、双敌方预警、争夺暂停、换手、归零获胜、低血量反攻、旧命令拒绝、控制权与暂停规则。

`python-tests.log`：41 项接口/LM/调度测试通过，其中新增 6 项预警测试，覆盖即时调度、旧请求淘汰、预算回退、楼内与炮组撤出。

`regression.log`：语义 113 项、集成 92 项、战斗 31 项、原夺旗/坦克 22 项、工作室 11 项、LM 23 项及动作/贴地检查通过。其中末尾首次 Python 检查发现并行新增 debug_visualize 后目录断言未更新，补齐控制台专用动作及 Agent 禁用断言后，完整 Python 复跑通过。

`browser.json`：最新导出在真实 WebGL 中操作夺旗、显示倒计时、暂停、接收预警、反攻、换手和归零获胜；包含实际版本和构建指纹。截图 `countdown.png`、`victory.png`。

浏览器端到端测试的 LM 采用 `tests/flag_warning_server.py` 中明确标识的受控测试客户端，不产生云模型调用费用。它验证 Godot 状态 → LM 输入/调度 → 合法指令 → 真实游戏执行的链路，不把固定测试策略称为云端模型表现；真实云端模型仍可能选择不同战术。

python3 tools/project.py test

DESKFRONT_URL=http://127.0.0.1:8783 PLAYWRIGHT_MODULE=/path/to/playwright node tools/flag_warning_browser_qa.cjs

主服务需要重新启动以加载新的 LM 策略模块；本次交付已更新服务和 Web 导出，旧浏览器页面需重新加载。

## 主服务真实模型核验

另从 8768 主服务读取了已有真实火山方舟调用日志（`live-lm-warning.json`）：输入中带有 30 / 27 / 25 秒明确预警；模型返回“立即进入旗圈阻断倒计时”的夺旗移动和清除守军的攻击意图，其中一次坦克夺旗移动已得到 Godot `applied` 回执。过期返回如实记录为 discarded。此核验未额外手工调用云模型。

最终页面与原生 HUD 文案调整后的导出由 Forge 门禁复验；主入口实际加载标识见 `main-game-live.json`，完整战斗交互验证的构建标识另保留在 `browser.json`。
