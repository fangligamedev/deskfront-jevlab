# 游戏设计

## AI 创作、指挥和复盘

项目面向 AI 创造可玩的战术挑战、玩家参与对抗、AI 总结战局的闭环。同一个模型连接分别担任关卡设计师、逐单位指挥官和战场分析员。设计师输出受约束的数据关卡，Python 与 Godot 验证后才允许加载；指挥官提交动作，Godot 执行；分析员读取按局采样和事件，输出可核对的战术分析。

具体流程和首版边界见 [AI 沙盒指南](studio/README.md)，机器接口见 [Studio API](studio/API.md)。设计意图与实际战况分开保存；通路可达不代表平衡或趣味性已获验证。

## 场景与目标

复古办公室中的白色桌面成为微型战场，人类缓慢操作电脑。三支塑料玩具兵小队分别为苔绿、钴蓝、砖红；每队三名步兵。三线争夺场、河谷双桥、前哨阵地由 JSON 配置。

独占中央旗圈守满 30 秒获胜，争夺时暂停、守方离开清零；歼灭不直接获胜。规则和坦克入场说明见 [中央夺旗](FLAG_MODE.md)，时间与增援条件由 data/battle.json 配置。重开恢复规则并更换 run_id，旧命令失效。

## 战斗体验

士兵优先活下来，利用方向掩体、姿态、压制和友军火力选择推进窗口。跑动用于转移，受压制时趴下爬行；隐蔽、探头、换弹、撤退由实时执行器完成。被绕侧的掩体不再提供原方向保护。

步枪单发，冲锋枪连射，火箭筒反装甲；手枪、手雷和近身刺刀可用。轻武器不能攻击坦克。射击经过实际首碰撞检测，掩体挡弹、爆炸受遮挡，破坏同时更新画面、碰撞和导航。

坦克独立转动炮塔，保持支援距离，遇近距离反装甲威胁或低血量撤离。反坦克炮可由健康步兵接管、推行、部署，受威胁时弃炮。当前是单人炮组，未实现多人装填协作。

蓝军使用桌面右上角两层小楼，沿楼梯进驻一楼或二楼、守窗、排队撤离。墙、窗和楼板分别参与弹道与破坏，楼板失效导致坍塌。

## 四种控制方式

| 模式 | 决策者 |
| --- | --- |
| 游戏 AI | 本地小队协调器和单位保命规则 |
| 模型 AI | DeepSeek 文本决策或 TypeSafe JEV 结构化选择；每名步兵与坦克独立请求，保留本地执行和自保 |
| 外部 Agent | 用户程序通过公开 HTTP 状态/动作协议 |
| 玩家 | RTS 鼠标键盘与控制台 |

控制权按阵营互斥，也支持全局切换。LM 和 Agent 的输出不是直接操纵内部状态；仍需通过引擎校验。所有人物、坦克和武器的状态见 [动作契约](AGENT_ACTION_STATES.md)。

## 控制台

深色策划页展示实际小地图、生命/压制、掩体预约、阶段、模型决策、预算、事件与回执。提供模式、武器、姿态、设施、地图、速度与规则调整。没有用固定数值伪造战术评分或模型信心。

## 验证与边界

交付证据见 [当前报告](DELIVERY.md)。原型不包含联网对战、战争迷雾、多智能体通信或大规模部队；单兵模型接入不代表成熟小队指挥。开放屋顶建筑用于俯视观察，不是完整室内结构模拟；碎块不是逐片导航障碍。TypeSafe JEV 通过官方 HTTP System One 接口接入，见 [JEV](JEV_CONTROL.md)。
