# 双人桌面 AI 演示

目标流程：玩家意图 → 合法关卡方案 → 导演逐项建场 → 桌缘派兵 → 双方夺旗 → 真实战局复盘 → 下一关。

打开 `/?view=demo`。选择“本地示例排练”，即可不依赖模型验证场景和交战；选择“AI 生成并进入演示”，由已配置文本模型设计关卡。界面显示实际供应商与控制模式，排练不会伪装成模型创作。

## 操作

1. 展开“演示意图与准备”，填写玩家意图。战斗控制可选游戏 AI、当前模型或外部 Agent。
2. 点击生成或排练。引擎加载两名站立玩家、一张桌子、两侧待命兵力。
3. 如需拍摄，点击“录制演示”，在浏览器系统选择器中选择需要录制的游戏窗口。
4. 点击“执行下一步”或“连续执行步骤”。导演每次只能选择 Godot 当前公开的合法编辑动作，等待执行回执后继续。
5. 关卡放置完成后，绿红双方各三名士兵从桌缘跑入部署位，全部就位才开始战斗。未上场单位不能开火、接令或占旗。
6. 独占中央旗圈守满关卡规定时间获胜。受伤/压制士兵仍自保；健康士兵可打破掩体交火僵持，分段推进。规则保留超时平局，任意生成关卡不保证一定有胜方。
7. 结束后点击“复盘并生成下一关”。服务端引用本局真实记录生成报告，将其 ID 与分析传入下一关设计任务。
8. 停止录制，下载视频和 JSON 时间线。可用时间线对齐建场、派兵、命令回执与胜负事件，再在 Premiere Pro 中剪辑。

## 模型角色

- **关卡与报告**：文本生成接口，当前使用火山方舟 DeepSeek。先产生完整 JSON 方案，再做 Schema、边界、碰撞和可达性验证。
- **建场导演**：可使用 TypeSafe JEV 的 typed-choice 接口，从当前合法放置/派兵/开战步骤中选下一步；也可使用文本模型返回受约束 step_id。
- **作战**：可选游戏 AI、逐单位模型或外部 Agent。游戏 AI 仍负责导航、动作、掩体、武器、生命和胜负规则。

当前是“模型设计完整方案，再逐步执行”。并非每一步任意生成新的网格或绕过验证；JEV 的选择接口和 DeepSeek 的文本创作接口是两种角色，不应混称为一个已经实现的端到端 JEV 生成器。

## 场景与录制边界

两名站立玩家是原创程序化几何人形，有轻微待机动作；不是新制作的 Blender 精细角色，也尚无手部取放玩具交互。绿红步兵使用现有骨骼资源及入场动画。蓝军作为保留阵营不参战。坦克在桌缘作为备用装备展示，当前演示不派遣；反坦克炮与建筑保留基础地图位置。

录像依赖浏览器 `getDisplayMedia` 与 `MediaRecorder`。内置浏览器可能拒绝录屏；请使用 Chrome/Edge 或系统录屏。是否录到声音取决于浏览器提供的音轨。视频优先 WebM；如 Premiere 不识别，请转为 H.264 MP4。尚未提供自动剪辑、自动发布或成片交付。
