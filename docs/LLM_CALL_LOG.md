# LLM 调用日志

策划台顶部点击 **LLM 调用日志**，即可打开日志窗口。选择一条调用，查看以下内容：

- 完整请求 JSON：模型名、system 提示词、user 战场状态及生成参数。
- 模型原始响应：保留收到的响应正文，包括 message 内容和 Token 用量；不是把解析后的行动重新包装成模型返回。
- 解析结果、校验错误、引擎 command_id 和执行回执。`wait` 表示保持行动，不伪造引擎执行回执。
- 请求开始时间、单位、局次、Tick、耗时和状态。坦克调用与步兵调用同样记录。

窗口每 2 秒更新，选中记录保持不跳转，便于阅读。可按单位筛选、加载更早调用，并导出选中的完整 JSON。关闭窗口不停止游戏；暂停游戏仍使用主界面的“暂停”。

日志从安装此功能后的调用开始记录，无法补回之前未保存的完整输入/响应。服务端在 `output/lm-calls.sqlite3` 本机数据库保存，重开游戏、刷新页面或重启服务后仍可查看。该目录被 Git 忽略。默认不自动清理历史，长期运行需自行归档。

API Key 和 Authorization 不进入请求日志。响应正文中的当前 Key、Bearer 凭证也会被脱敏；除脱敏和超大响应截断外保留原文。响应超过 128 KiB 时标记 `response_truncated=true` 并拒绝解析。网络超时等没有正文的失败显示错误信息，不生成伪造的模型回复。本地自保回退不会被记录为新的模型调用。

## 只读接口

- `GET /api/lm/calls`：最近 40 次调用的摘要，包含 `next_before` 和单位列表。
- `GET /api/lm/calls?before=123&unit=red-tank`：查看更早的指定单位调用。
- `GET /api/lm/calls/123`：读取某次调用完整输入、原始响应和回执。

摘要与完整输入分开传输，避免将大型提示词塞入高频 `/api/state` 战场同步。局次和控制权变化导致的旧回复保留为 `discarded`，不执行；模型或参数错误显示 `error` / `rejected`，成功收到引擎回执才显示 `executed`。

验证：`python3 -m unittest discover -s tests -p 'test_*.py'`。日志专项测试覆盖实际发送载荷与日志一致、原始无效 JSON 保留、回执关联、过期返回、持久化分页与密钥脱敏。
