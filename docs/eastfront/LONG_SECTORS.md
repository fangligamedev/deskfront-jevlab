# 三倍纵深关卡

2026-09-21：东西方向每段由 1.45 米延长到 **4.35 米**，南北宽度保持 **2.8 米**。这不是增加短关卡数量，也没有缩放士兵或坦克。

## 关卡与作战

- 慢脑收到实际尺寸和组件目录，每段规划 6–12 个组件。前沿、中段、后方构成完整阵地。
- 实时规划必须让前 3 个安全守军工位覆盖关卡纵深：至少一个位于前 1/3、一个位于后 1/3，整体跨度至少 40%。至少包含一段 0.65 米以上的战壕、沙包或墙。未满足则重新规划，并在调用日志保留原因。
- 守军在分配工位附近部署，继续由快脑下达意图、游戏 AI 执行进入掩体及战斗。旗点位于段内 x=4.13 米，保留其周围通行空间。
- 六种本地兼容布局的东西坐标与工事长轴同步乘 3。部队、装备、单个沙包尺寸不变，长防线通过重复沙包、木板和砖块组成。
- 工兵每个工位附近放置材料堆，横向与纵向长壕都有对应施工沟槽。沿用当前段交战、下一段可见施工与流式回收机制。
- 营区出发点移到东侧，减少无战斗的空地行军。默认近景保持可读性；玩家可向外缩放到 8 米视野。

## 配置与协议

`data/eastfront.json`：`width=4.35` 表示沿推进方向的段长；`half_depth=1.4` 表示南北半宽。`layout_limits` 统一 Python 和 Godot 的组件上限：最多 12 个，长宽各最多 1.8 米。接口仍接收旧的 3 组件布局，严格纵深约束只用于实时慢脑组合关卡。

现有对局不会在交战中强行拉伸；刷新新版本或点击“开始新东线”进入新尺度。默认仍是 DeepSeek 慢脑 + Laya 本地快脑。

## 验证

- Python 101 项测试；Godot 113 项语义检查。
- 长关卡与组件 28 项：包括三倍段长、末端旗点、守军纵深、正常尺寸沙包重复以及坦克通行/破坏。
- 六种兼容布局各 17 项战役部署检查、连续施工 18 项。
- 100 段流式推进契约 312 项通过；这是生命周期与回收测试，不是 100 局自主战斗胜率。
- Web 导出及真实浏览器使用 DeepSeek + Laya 验证，详细证据见 `docs/evidence/eastfront/long-sectors.json`。
