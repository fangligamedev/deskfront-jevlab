## 模型真实链路

新增 JEV / DeepSeek 独立下拉选项、运行时模型切换、旧回复隔离和凭证配置校验。JEV 的真实模型 `jev-1.13.0` 已返回防线模板并被 Godot 构筑，同时逐兵指令获得引擎执行回执。浏览器实测 JEV → DeepSeek → JEV 切换，构筑模型保持独立。此验证证明调用和执行链路可用，不代表战术胜率测评。

火山 Ark `deepseek-v4-flash-260425` 单题实测返回真实 logprobs，耗时 1911 ms；只是一次接口样本。

网页战斗实测使用 `deepseek_logprobs`：记录 71 轮请求计数、67 次响应、58 次引擎接受、5 次引擎拒绝，另有 2 次已死亡目标校验失败和 6 次时效/局次等丢弃统计。统计属于不同阶段，不能直接相加当作互斥样本。响应平均约 2.45 秒，累计输入输出 517,606 tokens，说明“短输出、多题并行”仍有重复输入成本。

该局在游戏 AI 与模型之间切换，推进至第三段；这不是纯模型胜率测评。日志保留实际 capture、attack、hold、wait 的概率和执行结果。布局生成另用短 JSON 选择防线，当前来源明确写为 `deepseek_json_frontier`，与逐兵 logprobs 区分。

[机器可读验收记录](../evidence/eastfront/verification.json) 只包含测试摘要和游戏状态，不含 API Key、dotenv 或用户附件代码。

## 如何继续扩展

- 当前内容是步兵与可破坏沙包的三种防线组合，不是任意 3D 场景生成器。后续可按组件契约加入战壕、楼房、反坦克炮和载具，再增加路径/射界验收。
- 东线没有关卡数量上限；活动窗口有限。极远坐标仍受浮点精度影响，尚未加入浮动原点；本轮不声称做过无限时长运行。
- 模型布局每局最多 128 次调用，战斗模型有单独轮数预算；超额或失败不伪装模型结果。模型构筑自动回退本地；战斗模型失效走既有本地自保，可随时切换游戏 AI。
- 逐兵战术效果仍取决于模型选择、响应延迟和实际局势，没有保证每局必胜。增加更多组件时应重新评估存活与推进平衡。
- 录像和 PR 剪辑沿用原演示工具；本轮没有声称已制作新的发布视频。

## 快慢脑迭代（2026-09-20）

新增 DeepSeek 三段规划缓存、JEV 双问题高频意图调度、两名工兵分阶段施工、六种不同布局、连续安全接敌、后方伤员治疗、全灭后的新小队波次。详见 [快慢脑使用说明](DUAL_BRAIN.md)。本节及新验收记录补充上文早期三模板版本的数据。


快慢脑专项检查 16 项、Python 78 项、原语义 113 项通过；100 段流式 312 项检查通过，回收 99 段。游戏 AI 在真实弹道与伤亡下约 127.85 游戏秒完成三段，116 次射击。另一次真实网页快慢脑运行推进六段、构筑八段、回收五段，约 120 FPS（单次本机样本）。

该网页运行记录三次慢脑规划和 154 次快脑引擎执行回执，同时出现网络请求失败与过期回复，游戏执行器仍持续运行。后续将快脑请求等待上限从 3 秒调至 5 秒并细分网络错误，不能把目标每两秒调度宣传成模型必定两秒返回。状态、统计和完整边界见 [专项验收 JSON](../evidence/eastfront/dual-brain.json)。
