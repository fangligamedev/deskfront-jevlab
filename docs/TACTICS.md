# 0.3.0 小队、CQB与坦克战术

本轮目标是让三人玩具小队有可观察的掩护关系，避免各自追敌或在没有支援时穿过开阔地。Godot仍是唯一战斗状态真相源。以下是独立编写的游戏行为规则，不是复刻《英雄连》的私有实现。

## 参考依据与边界

已完整读取用户提供的Chris Jurney《Company of Heroes Squad Formations Explained》4页PDF，检查嵌入队形图。页码按附件页序：

| 来源 | 设计启发 | 本工程实现 |
| --- | --- | --- |
| 第1页：稳定角色、未来位置/方向、行进速度修正 | 队伍不能只跟随队长当前坐标 | 步枪/冲锋枪/火箭筒角色稳定；共享虚拟锚点、预测1.4秒、按前后误差修正速度 |
| 第2页：柔性位置、有限寻路、重算迟滞、窄路队形 | 理想位置不应把跟随者送到墙另一侧 | 多级收缩候选位置、路线长度上限、0.028米目标迟滞、楔形/纵列切换 |
| 第3页：交替跃进、柔性撤退、虚拟领导 | 一人向掩体移动，其他人维持火力 | 小队协调器一次分配一名推进者；撤退沿队形路线偏向可达掩体 |
| 第4页：限制虚拟领导漂移、独立到达队形、互斥预约、破坏重寻路 | 单位到位后应分散并正确占据保护侧 | 0.17米锚点牵引限制、独立到达目标、掩体站位预约；破坏清空旧阻挡并重算 |

原文约2秒预测、软跃进约80%等为设计示例；本工程按桌面尺度调整参数。未实现完整core/left/right层级、原文自定义有界A*、用户拖拽指定到达朝向或完整班组资源调度。

用户补充的[GDC 2012：Believable Tactics for Squad AI](https://www.gdcvault.com/play/1015665/Believable-Tactics-for-Squad)已核对官方摘要，并抽查公开视频关键帧。约2分钟可见集中/涌现式设计比较；约25分钟为协同小队演示；约30分钟讨论方向偏好；约35分钟展示共享知识；约50分钟展示小队寻路。时间取自6秒切片边界，误差约6秒。未取得字幕，也未完整听译。

由此采用“共享小队阶段＋单兵局部执行”的混合方式，并把阶段、推进者、支援成员和理由直接展示给策划。本文的门控条件、权重、压制阈值、车辆规则是本项目自己的实现，不能归为演讲原公式。参考PDF、视频帧和播放流不随开源包发布。

## 士兵行为

1. **先入掩体**：按距离、主威胁朝向、多个敌人造成的暴露、射界、路线长度与站位占用选择。最多验证排名前8个站位的路线，旧站位有保留偏好。
2. **建立火力**：步枪负责掩护，冲锋枪优先突击，火箭筒独立关注装甲。角色不会因为队长死亡而互换；存活成员接替队长标识。
3. **交替推进**：通常保持至少2.4秒建立火力窗口，再分配一人向下一处掩体移动。接敌时至少有另一名静止、未换弹、非隐蔽、未被严重压制且有射界的成员；其他成员保持位置。推进到位/超时后恢复掩护阶段。
4. **绕侧清理**：敌步兵压制超过0.45或生命低于45%时，检查掩体端部。目标必须可达、有射界并使敌方方向保护失效；没有支援不执行。支援换弹或被压制导致火力中断时，暂停推进并就近找保护。
5. **回避无效阵地**：保护被绕开或掩体被摧毁时，一人重新占位，不能把原站位反复当成新的推进目标。
6. **撤退**：小队平均生命低于30%或平均压制超过0.9，向出生阵地撤离。采用偏向掩体的柔性队形，不在每个中间掩体硬停。暂无医疗补员，低血撤退不会自动复活。

普通行军由虚拟锚点沿共享路线推进，跟随者使用分散的预测位置。行军接敌立即撤销队形更新，避免下一次导航刷新覆盖已经发出的战斗站位。玩家与Agent接管会取消旧协调计划，不被游戏AI抢回控制。

## 桌面CQB

沙包、铅笔与书本属于低掩体：正确一侧减伤，允许越过射击；受压制或换弹时采用低姿。削笔器、灯座、托盘代理属于硬障碍：隐蔽位置的射线被遮挡，单位必须真实走到角落才有射界。探头停留从到达角落开始计时，换弹/受压制或停留结束后回缩。

高障碍采用线段与矩形精确相交，避免离散射线漏掉薄障碍。刺刀同时受低掩体与高障碍阻挡，不能隔沙包刺杀。现有动作表现为走位、蹲姿与枪械射击，没有新增写实贴墙动作、室内破门、投掷物或多人入室清扫。

## 坦克

坦克使用扩张障碍后的独立导航，采样可达射击位置并回避与友军步兵重叠的终点。已经处于合适距离且有射界时保持支援，不反复执行一个固定坐标。

近距离可见火箭筒或低血量触发拉开距离：车体沿路径倒退，炮塔独立跟踪目标。炮塔对准才开炮，弹丸从Blender导出的Muzzle位置产生。前/侧/后装甲承伤系数分别0.72/1/1.4，鼓励反坦克兵寻找侧后方。暂未模拟履带损坏、穿深、弹跳或炮塔自身装甲区。

## 验证与已知限制

`tests/tactics_checks.gd`使用真实Godot单位与导航建立可重复场景，检查隐蔽时不可开火、实际探头后射击、回缩、单人侧翼、失去支援中止、接敌停止队形、破坏后的格子通行、坦克倒车和炮塔独立旋转。`tests/tactics_soak.gd`跑3个固定种子并记录真实战斗状态；浏览器测试验证RTS输入和状态接口。

当前仍是三人小队、全局完全信息、简化二维桌面导航。小队只有一组活动行军锚点，不能当成大型RTS任意多编队系统。掩体和路线评分是启发式，未做完整危险场积分或战争迷雾；实际CQB绕侧只在条件允许时发生，不为了演出强制冲锋。三组默认战局均由获得坦克的红方获胜，不能据此宣称阵营平衡完成。Jev仍未接入。
