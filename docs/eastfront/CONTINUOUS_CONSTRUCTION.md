# 东线：战斗期间提前构筑右侧

此前施工由绿色小队与已建地图边缘的距离触发；队员在当前防线停留或被压制时，下一段一直不申请。慢脑又等缓存耗尽才再规划，容易在段落衔接时暴露网络延迟。

现在当前段开战后即准备右侧下一段，保留一个可见的施工/就绪缓冲。工兵照常挖壕、运料与堆砌，当前战斗持续推进；未完工的下一段不加入沙包碰撞，预备守军不会提前攻击。下一段完工也不重置当前旗点、士兵路线或镜头。夺旗后直接激活已准备好的阵地，全程保持同一局次。

DeepSeek 缓存剩两段时，后台预取下一批三段。新旧方案合并，保留尚未消耗的方案与各自原始模型调用编号；过期缓存按推进位置回收。前台仅显示施工/后台规划状态，不弹出阻塞窗口或暂停游戏。世界仍保留最多四段；不会通过无上限堆积场景换取预加载。

验证：18 项连续性断言通过；113 项原有语义检查、93 项 Python 测试、17 项快慢脑执行检查通过。100 段流式压力测试的 312 项断言通过（模拟占点检查回收，不代表 100 场自主战斗获胜）。Web 实测记录当前段交战与下一段施工同时存在，并保持同一局次与递增 Tick。

入口仍默认 DeepSeek 慢脑 + 本地 Laya 快脑。已有战斗不依赖规划返回逐帧运行。长期网络故障若耗尽已缓存关卡，仍需等待真实方案；不会偷偷用随机模板代替慢脑。

验证备注：Forge 聚合检查本次在语义场景的 120 秒上限处超时，其包装器随后报错；单独执行同一语义检查已得到 113 项通过，未把聚合检查记录为通过。真实模型曾因缺少禁用坦克字段、输出未支持武器而被拒；现已在规划协议中明确枚举与必填字段，并把上一轮校验错误回传给慢脑。
