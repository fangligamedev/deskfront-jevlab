# 无尽东线：边推进、边构筑

这是独立于原中央夺旗战的一种连续扇区玩法。绿色远征队从西侧出发，沿屏幕左→右（世界 +X）攻占不断接续的防线。Godot 保留移动、弹道、掩体破坏、伤亡和占领的唯一执行权。

新增：[快慢脑玩法与接口](DUAL_BRAIN.md)。推荐使用 DeepSeek 规划、JEV 调度、游戏 AI 连续执行。

## 开始玩

启动原有服务后打开 `http://127.0.0.1:8768/?view=eastfront`，或点击顶部 **无尽东线 →**。新引擎直接进入本地种子生成的东线；若正在观察另一窗口，视图切换继续连接同一局，点击 **开始新东线** 才换局。

- **前沿构筑**：本地种子生成无需 API；明确选择 **JEV · 动态构筑防线** 或 **DeepSeek · 动态构筑防线**，与士兵指挥模型独立。
- **远征队控制**：游戏 AI、玩家、**JEV · 逐兵战术指挥**、**DeepSeek · logprobs 多题指挥**、外部 Agent。选择后可开新局，也可点击“应用控制方式”接管本局。
- **实际操作**：拖框选兵、右键移动、滚轮缩放、中键/Alt 拖动或方向键平移。手动平移会退出自动跟随，可点击“跟随远征队”恢复。
- **目标**：当前旗点内有绿军且无红军，累计守住 5 秒；争夺暂停、绿军全离开则归零。占领后目标向东移动。
- **补给**：存活队员恢复最多 30 HP、补满弹匣和两枚手雷；队员不足三人时，每段提供一名新编号补员，从已控制的后方步行跟进。阵亡者不会复活。
- **后续小队**：绿色全员阵亡后等待 5 游戏秒，从左侧部署新编号三人小队；已占领进度保留。没有预设最后一关。
- **记录**：导出东线记录可获得当前状态和最近 80 条构筑事件；详细历史写入本机 `output/session.jsonl`。调用输入、原始返回和回执仍在原 LLM 日志窗口。

同一局可切回策划网页、战术执行和放大游戏视图。独立窗口沿用原产品行为：启动新的引擎会话，不会复制正在进行的对局。原中央夺旗与双人演示保留。

## 启动命令

```sh
python3 tools/project.py import
python3 tools/project.py web
python3 tools/server.py --port 8768
```

原生 Godot 可直接使用 `godot --path . -- --eastfront`；若要连接控制台，请设置 `DESKFRONT_URL` 为该服务地址。模型秘钥仍只放本机 `.env`。

启用附件思路的 DeepSeek 多题决策：

```sh
DESKFRONT_LM_PROVIDER=deepseek_logprobs python3 tools/server.py --port 8793
```

需要已经配置的 `ARK_API_KEY` 与 `DESKFRONT_LM_MODEL`。打开该端口的东线页，在远征队控制选择 **DeepSeek · logprobs 多题** 后应用。没有 Key 时仍可使用本地生成和游戏 AI。

## 生成与执行链路

JEV 使用服务端 `TYPESAFE_API_KEY` 与 `TYPESAFE_MODEL`。页面可以直接切换战斗模型，无需重启服务。模型选择影响所有处于模型控制的阵营：界面先交还游戏 AI、等待引擎确认，再切模型并恢复模型控制；旧回复丢弃，预算不重置。未配置的模型会明确报错。前沿构筑选择点击“开始新东线”后生效，每段记录显示实际来源。

1. 前锋接近已提交边界 0.9 米内，引擎发出带局次、递增序号和合法模板的请求。
2. 本地按种子选模板，或服务端模型参考小队状态和近期防线选择一个模板。
3. 引擎检查序号、占用冲突、组件边界、出生点和实际导航通路。模型无法直接改坐标、血量或已占用地形。
4. 两名工兵分步挖掘、搬运、堆砌，约 12 游戏秒；完成后才激活掩体碰撞、弹道遮挡和导航。
5. 前方守军等待所属扇区开启，再进入真实战斗。待命守军不能提前开火，也不能被提前攻击。
6. 占领触发补给并开放下一目标。后方安全区退出窗口时回收地板、掩体、尸体和导航缓存；不能回收仍有友军的区域。

最多在场四段，最多提前准备两段（相对已占领数）。模型选择超过 14 秒有效等待时间未被采用，则明确标记 `local_timeout_fallback`。模型不提供结果时，游戏仍可继续。晚到的回复不能覆盖已提交区块。

后方残余敌军只有脱离远征队火力接触后才随窗口退出，记录为 `rear_disengaged`，不算击杀。内存中的世界窗口和事件有限；磁盘历史日志保留完整记录，因此长期运行仍应管理 `output` 的磁盘空间。

## 扩展组件

编辑 [data/eastfront.json](../../data/eastfront.json) 的 `templates`：

```json
{
  "id": "my_defense",
  "name": "我的防线",
  "covers": [[0.40, -0.30, 0.055, 0.26]],
  "enemies": [[1.05, 0.18, "rifle"]]
}
```

掩体格式为局部 `[x, z, x宽, z深]`（米）；当前是 0.06 米高、100 HP 的可破坏沙包。守军格式为 `[x, z, 武器ID]`，支持 `rifle/smg/rocket/pistol`；身份为每段唯一的 `red-e段号-序号`。现有六种模板，增加曲折浅战壕、补给站包围战和窄口封锁线，旗点位置、地表配色及敌军配备随模板变化。换模板后重新开局；源码运行即时加载 JSON，Web 版本需要重新导出。

这是**组件组合式生成**，不是实时生成任意 3D 模型。新战壕、楼房、炮位、载具组件应先扩展组件 schema、导航/射线几何及生成验证器，再加入模型候选；不能只把文件放进 assets 就假定可用。现版东线为步兵突破，原坦克增援在此模式禁用，避免原桌面坐标处“幽灵开炮”；原有夺旗地图仍支持坦克与反坦克炮。

配置 `width`、`half_depth` 属于工程级修改，需要同步初始营区范围与模板验证；当前为东西 4.35 × 南北 2.8 米（half_depth=1.4）。其他已实现的数值参数见 JSON。没有加入无限距离浮动原点，极远坐标精度仍受 Godot 浮点数约束；已验收范围见交付报告。

## 参考方案的使用边界

本机平台跳跃工程提供了有限前方库存、校验后提交和超时后备的实现参考；合金弹头工程提供按需编译与准备窗口的设计参考。所找到的暗黑工程仍是起步项目，没有把其描述成已完成的同等流式系统。本工程保留自己的 Godot 战斗权威，没有引入浏览器决定命中或伤亡。
